# platform-runtime Specification

## Purpose

为管理平台提供一致、可观测且不泄露敏感信息的后端运行时边界，使前端与后续业务模块可稳定发现服务和数据库可用性并获得可处理的失败响应。

## Requirements

### Requirement: 版本化服务健康状态
系统 SHALL 提供无需认证的 `GET /api/v1/health`，返回服务和数据库的当前可用状态，且不得返回凭据、连接字符串、内部堆栈或业务数据。

#### Scenario: 服务与数据库均可用
- **WHEN** 客户端请求健康检查且数据库连接成功
- **THEN** 系统返回 HTTP 200 和机器可读的服务、数据库健康状态

#### Scenario: 数据库不可用
- **WHEN** 客户端请求健康检查且数据库连接失败或超时
- **THEN** 系统返回非成功状态和明确的数据库不可用状态
- **AND** 响应不暴露数据库凭据或内部异常详情

### Requirement: 统一 API 失败响应
系统 SHALL 为 API 路由返回统一、机器可读的错误结构，包含稳定错误码和关联标识；未处理异常 SHALL 映射为通用服务错误而不得向客户端暴露堆栈。

#### Scenario: 请求不符合契约
- **WHEN** 客户端提交无效的请求路径、参数或请求体
- **THEN** 系统返回对应的 HTTP 失败状态、稳定错误码和可供界面展示的错误信息

#### Scenario: 内部处理失败
- **WHEN** API 路由发生未处理的内部异常
- **THEN** 系统返回通用服务错误和关联标识
- **AND** 客户端响应不包含堆栈、数据库连接信息或秘密配置

### Requirement: 安全的运行时配置与日志
系统 MUST 从运行时环境加载秘密配置，并输出带关联标识的结构化应用日志；日志 MUST 不包含密码、令牌、Cookie、连接字符串或其他秘密值。

#### Scenario: 缺少必要秘密配置
- **WHEN** 应用以生产配置启动但缺少必要秘密配置
- **THEN** 应用拒绝进入可服务状态并输出不含秘密值的诊断信息

#### Scenario: 请求处理被记录
- **WHEN** 系统完成或拒绝一个 API 请求
- **THEN** 应用日志包含时间、级别、关联标识、请求结果和必要诊断上下文
- **AND** 日志不记录请求中的秘密字段
