## Why

当前本地登录包含 Cookie 会话、账号状态、密码规则、来源校验和前端路由守卫等附加认证安全机制，超过项目实际需要。平台只需要在登录时校验用户名和密码是否匹配，因此应将认证能力收敛为一次性的凭据校验。

## What Changes

- **BREAKING** 保留用户名和密码登录；登录成功后仅设置保存用户 ID 的 Cookie，后续请求据此加载用户身份以执行既有授权与审计。
- **BREAKING** 登录仅校验用户名与密码是否匹配，不再校验账号状态、密码复杂度/长度、请求来源、会话时效或其他附加认证条件。
- 保留前端身份恢复并增加轻量路由守卫：访问业务页面但未获取到当前用户时跳转登录页，登录成功后返回原页面；移除退出入口和认证附加校验处理。
- 更新 `openspec/config.yaml`：后续开发仅允许用户名密码匹配和用户 ID Cookie 身份传递，不得新增 Cookie 签名、过期、来源校验、账号状态、令牌或其他认证附加机制。
- 非目标：不引入 SSO、MFA、授权、角色访问控制、访问令牌或其他替代认证方案；密码继续以摘要保存，但该存储保护不作为额外登录判断条件。

受影响需求基线：`doc/OTS-需求规格说明-V1.6.md` 中与本地账号认证有关的内容。依赖 change：无。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `local-authentication`: 将本地认证收敛为仅校验用户名和密码的登录行为，并移除其余认证机制。

## Impact

- 后端：认证服务、路由、配置和测试；保留登录和用户 ID Cookie 解析，删除 Cookie 签名、来源和账号状态校验。
- 前端：保留登录页、登录 API 客户端及基于用户 ID Cookie 的身份恢复；增加仅依据当前用户接口结果的轻量路由守卫，移除退出和认证附加校验处理。
- 数据库：保留用户表、密码摘要和既有数据；不执行删除表或数据的迁移。
- OpenSpec：更新本地认证规格和项目配置，持久化“仅用户名密码校验”的约束。
