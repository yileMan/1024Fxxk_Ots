## Context

参见 `proposal.md` 的 Why。OTS-19 已有按当前有效产品版本范围裁剪的漏洞/评估查询，OTS-14/15 已把提交与审核人员、时间、结论和修订快照保存在 `product_assessment`。当前系统没有通用后台任务表，V1 限定 11 张应用基础表；`import_batch` 专用于离线导入状态，不适合承载只读导出。

需求只规定“完整评估表”、UTF-8、稳定列和大结果流式响应，没有规定 XLSX、异步任务或历史修订语义。本设计把“完整”解释为指定 `product_ots` 范围内全部状态的当前修订，并将尚未形成的字段保留为空；这样导出集合与当前授权查询一致，同时不会把候选推断为产品结论。

## Goals / Non-Goals

**Goals:**

- 固定可被 Excel 和通用工具稳定读取的 CSV 字节、列、排序、空值及转义契约。
- 预检与下载共用同一范围解析、授权和当前评估查询，避免页面数量与下载集合发生定义漂移。
- 使用有界内存流式生成大结果，并在请求取消后及时释放数据库资源。
- 保持全部导出路径只读，不改变评估状态且不写数据库变更审计。

**Non-Goals:**

- 不建立异步导出任务、进度轮询、导出历史、临时文件、对象存储或下载续传。
- 不支持 XLSX、ZIP、自定义字段、自定义排序、跨多个产品版本/OTS 的批量导出。
- 不导出历史修订链、完整来源 JSON、内部候选证据 JSON 或跨产品参考。
- 不改变 OTS-19 查询、评估状态机或产品范围模型。

## Decisions

### 1. 用两个只读端点分离确认信息与文件传输

新增：

- `GET /api/v1/assessment-exports/preview?product_version_id=...&ots_id=...`：返回产品、版本、OTS 的安全显示摘要和 `row_count`；
- `GET /api/v1/assessment-exports/csv?product_version_id=...&ots_id=...`：返回 `text/csv; charset=utf-8` 的流式附件。

两个端点调用同一 service 完成身份、有效范围、产品版本/OTS 从属关系和当前评估集合解析，并在各自请求中独立授权。预检不签发可复用令牌；因此预检与下载之间数据可能变化，页面将预检数量标为确认时快照，下载以下载请求开始时的数据库快照为准。

替代方案是在一次 POST 中创建导出任务并轮询状态。它需要任务持久化、清理、恢复和鉴权模型，与请求内流式响应及 11 表约束冲突，因此不采用。只提供下载端点则无法在不下载文件的情况下展示确认数量，也不采用。

### 2. CSV 使用带 BOM 的 UTF-8 和固定十九列

响应开头写入 UTF-8 BOM，随后使用 RFC 4180 兼容写入器生成中文表头和行；行结束符固定为 CRLF。列固定为规格列出的十九项，时间使用带时区的 ISO 8601，数值使用句点作小数点且不添加本地化千分位，枚举输出稳定业务中文值。JSON 或多值来源内容不直接进入 V1 导出。

文件名采用 ASCII 安全标识，例如 `assessment_export_pv-{product_version_id}_ots-{ots_id}_{YYYYMMDD}.csv`，并同时提供 RFC 5987 `filename*` 的可读名称；所有名称组件先移除控制字符和路径分隔符。

替代方案是 XLSX，它需要新依赖并天然倾向在内存或临时文件中组装工作簿；需求只要求 UTF-8 和稳定列，CSV 更符合最小实现。无 BOM 的 UTF-8 更纯粹，但部分桌面 Excel 会误判中文编码，因此采用 BOM。

### 3. 当前修订全集而非仅已审核评估

查询以一个合法 `product_ots.id` 为根，选择 `product_assessment.is_current = 1` 的全部状态，关联 `vulnerability` 和必要显示字段，并按 `vulnerability.cve_id ASC, product_assessment.id ASC` 排序。审核列仅在真实审核快照存在时输出；未提交、未审核字段为空。来源评分/向量读取当前评估修订保存或关联的来源事实字段，环境评分/向量读取该产品评估字段，不执行重新计算。

这样“完整评估表”包含工作中和已完成项目，并准确表达状态；仅导出 `completed/approved` 会使页面当前查询中的未完成行静默消失。历史修订由 OTS-19 追溯能力负责，本导出不重复它。

### 4. 范围解析与错误响应避免授权侧信道

先解析当前用户有效版本范围，再验证请求范围。管理员以全局范围处理；普通用户若版本不在有效范围，立即返回统一 `403`，不继续检查 OTS 是否存在或关联。对已授权版本，缺失对象返回 `404`，格式错误返回 `422`，合法但无评估的预检返回 `200` 与零行，下载返回 `409 export_empty` 以阻止空文件。

前端产品版本选项复用授权后的版本 API，OTS 选项只查询该版本下的关联项；但后端始终执行独立校验，不能依赖隐藏选项保证安全。

### 5. 使用 keyset 分批查询和生成器流式写出

下载 service 在一个短只读事务的一致读取快照内，以 `(cve_id, assessment_id)` 为游标分批查询。每批映射为轻量投影，逐行经 CSV 写入器产生字节块后释放；禁止 ORM 懒加载和逐行补查。首批数据与表头在响应提交前准备，使授权、空集合和初始数据库错误仍能返回 JSON 错误；响应开始后的数据库或连接失败只能中止传输并记录结构化应用错误，客户端将不完整下载视为失败。

替代方案是 offset 分页，长结果后段成本增加，且并发更新可能导致重复/遗漏；全量查询则违背有界内存目标。单个一致读取事务可能延长 MVCC 快照，因此批大小和代表性规模需以 MySQL 测试确定，并监控事务持续时间。

### 6. 浏览器下载使用流式响应且不误存错误体

页面先调用 preview 并显示范围和数量，用户确认后调用下载 API。API client 先验证 HTTP 状态与 `Content-Type`，成功时使用浏览器文件下载能力消费响应；JSON 错误映射为现有统一错误模型，不创建 `.csv`。下载期间按钮禁用并提供取消入口；取消通过 `AbortController` 终止请求，后端生成器感知断开后关闭结果集和会话。

浏览器原生下载对精确字节级进度支持不一致，页面状态定义为“准备中/下载中/完成/失败”，不承诺百分比。若实现采用 Blob 兼容路径，必须通过代表性大文件内存测试；优先使用支持流式落盘的现有浏览器机制，且不得在前端重新解析或重组 CSV。

### 7. 导出链路不接入审计服务

preview 与 csv 路由只建立只读数据库会话，不调用 `AuditService`，不更新“最后导出时间”或任何业务记录。应用结构化日志可以记录请求结果、耗时、行数和非敏感范围 ID，但不得记录导出正文、分析依据、审核意见或 Cookie；应用日志不属于 `audit_log`。

## Risks / Trade-offs

- [预检后数据变化导致确认数量与下载行数不同] → 页面明确预检是确认时快照，下载在独立一致读取中形成最终集合；不为强一致引入锁或持久化任务。
- [长时间一致读取增加 MySQL undo 保留压力] → 使用 keyset、小批量轻投影和代表性最大规模测试，记录耗时与峰值内存；超出 V1 门槛时再提出异步导出 change。
- [响应开始后失败无法改回 JSON 错误] → 在提交响应前完成授权和首批查询；传输中失败立即中止并记录日志，前端检测失败，不提供看似成功的完整文件。
- [CSV 公式注入影响电子表格用户] → 对以 `=`, `+`, `-`, `@`, tab 或 CR 开头的自由文本单元格加前导单引号，并保留相应契约测试；标识、枚举、时间和数值使用类型化格式化，不进行自由文本拼接。
- [当前修订全集包含未完成或被退回内容] → 导出权限与平台当前查询一致，明确输出状态及空审核列；不跨授权范围，也不把该文件定义为“仅最终批准报告”。
- [下载文件名泄露业务名称] → ASCII 回退名仅含内部数值 ID；可读 `filename*` 只在授权成功后返回并进行控制字符与路径字符清理。

## Migration Plan

1. 先增加范围、授权、CSV 字节和只读性失败测试，不改变数据库。
2. 实现 preview/csv 契约、投影查询与流式生成器，生成 OpenAPI 和 TypeScript 类型并验证连续生成无漂移。
3. 实现评估导出页面、联动选择、确认、取消和错误处理，运行组件测试与系统 Chrome E2E。
4. 在真实 MySQL 8 代表性大结果上验证行集合、稳定排序、一致快照、峰值内存、取消释放和执行计划；不得新增表，只有执行计划证明确有必要时才另行评估既有表最小索引。
5. 部署时先发布后端再发布前端；回滚时先回滚前端再回滚后端。无数据迁移、临时文件或持久化任务需要清理。
