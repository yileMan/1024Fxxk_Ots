## Why

平台已有本地用户、固定角色、产品/版本主数据和 OTS 清单，但普通用户尚缺少可持久化、可统一执行的产品访问边界。OTS-05 需要在后续采集、评估、审核、查询和导出能力进入开发前，建立产品级与版本级授权的唯一规则，避免不同接口或前端入口产生越权差异。

## What Changes

- 新增 `user_product_scope` 授权能力，由管理员按产品或产品版本为用户查询、授予和撤销范围，并对成功变更记录审计。
- 产品级授权覆盖该产品全部有效版本；版本级授权仅覆盖指定版本；多个授权按并集计算，重复授权保持幂等。
- 管理员具有全局产品/版本访问能力；非管理员必须同时满足固定角色、产品范围及后续业务接口声明的负责人/审核人条件。
- 建立后端统一授权依赖与范围查询规则，供列表、详情、写入、评估、审核和导出接口复用；直接请求 API 与通过页面访问执行相同校验。
- 在用户管理中提供授权配置交互，并按角色与范围裁剪导航、列表和操作入口；越权路由展示明确的 403 页面，但前端隐藏不作为安全边界。
- 通过编号化 MySQL SQL 脚本新增 11 张应用基础表中的 `user_product_scope`，提供升级验证与回滚说明，不新增其他业务表。
- 覆盖需求 `FR-USER-003`、`FR-USER-004`，并落实权限规则 1～2、5～9 中与本 change 有关的范围、固定角色、当前人员分配及历史保护边界。
- 依赖已归档的 `ots-02-user-role-administration`、`ots-03-product-version-management`、`ots-04-ots-bom-management`。
- 非目标：本 change 不实现评估状态机、自审校验动作、审核动作、数据导入或评估导出；不提供自定义角色或权限矩阵，也不改变现有本地认证形式。

## Capabilities

### New Capabilities

- `product-scope-authorization`: 定义管理员维护产品/版本授权、服务端统一范围裁剪、角色与负责人/审核人约束、前端权限反馈及授权审计。

### Modified Capabilities

- `product-version-management`: 将产品与版本的读取从管理员专用调整为管理员全局可读、普通用户按有效产品范围裁剪，同时保持主数据写入仅管理员可用。
- `ots-bom-management`: 允许普通用户按有效产品版本范围读取该版本的 OTS 清单，同时保持 OTS 主数据、关联写入和 CSV 管理仅管理员可用。

## Impact

- 数据：新增基线表 `user_product_scope` 及其外键、唯一键和查询索引；授权增删与 `audit_log` 同事务提交。
- 后端：新增授权模型、Schema、Repository、Service、管理员授权 API 和可复用的范围解析/校验依赖；既有产品、版本及 OTS 读取入口接入统一规则时保持管理员行为兼容。
- 前端：扩展用户管理详情的授权配置，增加统一权限状态、范围裁剪和 403 页面，并从 OpenAPI 生成对应 TypeScript 类型。
- 测试：增加角色与范围矩阵、产品级/版本级包含关系、直接 API 越权、停用实体、并发/事务失败、前端路由和纵向授权场景测试。
- 后续影响：OTS-06～23 的产品相关接口必须复用本 capability，不得各自定义不同的范围判断。
