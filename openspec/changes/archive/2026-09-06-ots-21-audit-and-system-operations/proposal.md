## Why

系统已经在多个写入流程中直接生成 `audit_log`，但缺少统一覆盖复核、可查询的变更记录页面和运行状态视图，无法完整验收 FR-AUDIT-001～003 及系统方案 11.3。OTS-21 将这些能力收敛为一个管理员可验收的纵向切片，并为后续 OTS-22 的备份与恢复交付提供状态展示契约。

## What Changes

- 统一审计写入契约并复核现有核心业务写路径：只为最终成功提交的 `insert`、`update`、`delete`、`batch_upsert` 记录审计，审计与业务变更处于同一事务；幂等无变化和失败回滚不留记录。
- 统一 `detail_json` 的关键字段差异表达、敏感字段脱敏与批量汇总规则；批量导入只按批次记录汇总，不逐条生成漏洞事实审计。
- 新增管理员只读的数据库变更记录查询 API 与“系统管理－变更记录”页面，支持对象、用户、动作、时间筛选、稳定分页及关键字段差异查看。
- 明确变更记录为系统追加写入；不提供修改、删除或清理 API，普通用户不能查询、修改或删除记录。
- 新增管理员只读的系统运行信息 API 与“系统管理－运行状态”页面，展示应用版本、数据库连通状态、磁盘剩余空间、最近备份、最近导入和最近失败，并对未知、过期或故障状态给出明确反馈。
- 保留 `GET /api/v1/health` 作为不暴露内部详情的基础存活检查；详细运行信息必须登录且仅管理员可见，探测失败时以分项状态返回，不因单一依赖故障丢失其他诊断信息。
- 登录、纯查询、导出、备份执行以及失败事务均不写 `audit_log`；应用安全日志和结构化运行日志不纳入数据库变更记录。
- 不实现备份、恢复、调度、告警发送、独立监控平台、审计哈希链、SIEM、客户端地址记录或审计记录清理；这些不属于 OTS-21 的交付边界。

## Capabilities

### New Capabilities

- `audit-and-system-operations`: 定义成功数据库变更的统一审计边界、管理员只读查询与差异查看，以及应用、数据库、磁盘、备份和导入运行状态的安全展示契约。

### Modified Capabilities

无。

## Impact

- 后端：复核并集中现有审计构造规则，新增审计查询与系统运行信息的 schema、repository/service 和只读 API；继续复用 `audit_log`、`app_user`、`import_batch` 等现有 11 张表。
- 前端：新增“系统管理－变更记录”和“系统管理－运行状态”路由、导航入口、筛选分页、差异详情及故障/未知状态反馈；契约由 OpenAPI 生成 TypeScript 类型。
- 数据与运维：不新增业务表；如现有 `audit_log` 索引经真实 MySQL 执行计划证明足够，则不新增迁移。最近备份只读取约定备份状态文件或配置目录中的受限元数据，不执行备份；缺少 OTS-22 产物时显示“未配置/无记录”。
- 权限与日志：详细变更记录和运行信息仅管理员可读，普通用户统一拒绝；健康检查不泄露路径、凭据、SQL 错误或主机内部细节。
- 需求基线：覆盖 FR-AUDIT-001、FR-AUDIT-002、FR-AUDIT-003、关键验收规则 19、可靠性约束 12.3 与系统方案 11.3。
- 依赖 change：OTS-02 `ots-02-user-role-administration`、OTS-10 `ots-10-assessment-task-generation`、OTS-15 `ots-15-return-revision-resubmit`；与 OTS-22 `ots-22-deployment-backup-restore` 通过备份状态文件契约衔接。
