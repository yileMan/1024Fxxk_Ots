## Purpose

本能力用于保证核心业务数据库变更具有一致、可追溯且不可由用户篡改的记录，并让管理员在不引入独立监控平台的前提下查看应用、数据库、磁盘、备份和导入的关键运行状态。

## ADDED Requirements

### Requirement: 只审计成功提交的数据库变更
系统 MUST 仅为核心业务数据最终成功提交的 `insert`、`update`、`delete` 和 `batch_upsert` 写入 `audit_log`，并 MUST 使业务变更与对应审计记录处于同一数据库事务。幂等请求未造成实际数据变化时 MUST NOT 新增审计记录。

#### Scenario: 业务变更与审计共同提交
- **GIVEN** 已登录用户获准修改一个核心业务对象
- **WHEN** 该对象的数据库变更成功提交
- **THEN** 系统同时提交一条动作类型与实际写入一致的审计记录
- **AND** 业务对象和审计记录对后续查询同时可见

#### Scenario: 事务失败不留审计
- **GIVEN** 一个写请求已经暂存业务变更及审计记录
- **WHEN** 校验、并发冲突、数据库异常或其他原因使事务回滚
- **THEN** 系统 MUST NOT 保留业务变更或本次审计记录

#### Scenario: 幂等无变化不留审计
- **GIVEN** 请求内容与数据库当前状态相同且服务按幂等成功处理
- **WHEN** 请求未造成任何核心业务字段变化
- **THEN** 系统 MUST NOT 新增审计记录

### Requirement: 排除非数据库变更活动
系统 MUST NOT 因登录、纯查询、导出、备份执行或健康与运行状态探测写入 `audit_log`；登录安全事件如需追踪 MUST 使用独立应用安全日志且不得伪装为数据库变更记录。

#### Scenario: 只读活动不入审计
- **GIVEN** 审计表当前记录数已知
- **WHEN** 用户成功或失败地执行登录、列表查询、详情查询、评估导出、审计查询或运行状态查看
- **THEN** 审计表记录数和内容保持不变

#### Scenario: 备份活动不入审计
- **GIVEN** 外部备份流程执行成功或失败并更新其状态产物
- **WHEN** 系统读取并展示该备份状态
- **THEN** 系统 MUST NOT 为备份执行或状态读取新增数据库变更记录

### Requirement: 审计记录包含可追溯且脱敏的关键差异
每条审计记录 MUST 包含操作时间、对象类型、动作，并在适用时包含操作者、对象 ID 和 `detail_json`。新增记录的 `detail_json` MUST 保存关键初始值，更新记录 MUST 保存实际变化字段的前后值，删除记录 MUST 保存识别信息及删除原因；系统任务允许操作者为空。密码、密码摘要、Cookie、完整分析长文本、审核意见全文、原始导入正文及其他敏感内容 MUST NOT 写入审计详情。

#### Scenario: 更新只记录实际关键差异
- **GIVEN** 一个核心业务对象同时包含已变化、未变化和敏感字段
- **WHEN** 更新成功提交
- **THEN** 审计详情按稳定结构保存已变化关键字段的 `from` 与 `to`
- **AND** 未变化字段和敏感原值不出现在详情中

#### Scenario: 系统任务没有操作者
- **GIVEN** 后台任务在没有交互用户的情况下成功修改核心业务数据
- **WHEN** 事务提交
- **THEN** 审计记录的操作者允许为空
- **AND** 对象、动作、时间及必要的批次或变化摘要仍可追溯

#### Scenario: 批量导入使用汇总记录
- **GIVEN** 一个合法导入批次新增或更新多条来源事实并生成相关候选或评估任务
- **WHEN** 整个导入事务成功提交
- **THEN** 系统以 `batch_upsert` 记录批次号和各类新增、更新、未变化数量
- **AND** 系统 MUST NOT 为每条来源事实生成一条独立审计记录

### Requirement: 管理员可筛选和分页查询变更记录
系统 SHALL 提供管理员只读变更记录查询，支持按对象类型、操作者、动作、开始时间和结束时间的交集筛选，并按 `created_at DESC, id DESC` 稳定排序。查询 MUST 使用有界分页，返回结果总数和可继续导航所需信息；所有时间按明确时区契约传输。

#### Scenario: 组合筛选返回交集
- **GIVEN** 审计表包含多个对象、用户、动作和时间的记录
- **WHEN** 管理员同时提交合法的对象、用户、动作及闭区间时间筛选
- **THEN** 系统只返回满足全部条件的记录
- **AND** 相同时间的记录按 ID 降序保持稳定

#### Scenario: 未筛选查询使用有界分页
- **GIVEN** 审计记录超过单页上限
- **WHEN** 管理员不带筛选条件请求第一页并继续分页
- **THEN** 每个响应不超过服务端页大小上限
- **AND** 导航过程中记录顺序稳定且不因同时间值发生页内重复

#### Scenario: 非法筛选被拒绝
- **GIVEN** 管理员提供未知动作、结束时间早于开始时间、非法对象类型或超出上限的页大小
- **WHEN** 查询请求到达服务端
- **THEN** 系统返回 `422` 且不执行宽范围降级查询

### Requirement: 变更记录查询和详情不可被业务用户篡改
变更记录列表、单条详情和差异查看 MUST 仅允许管理员访问。系统 MUST NOT 提供修改、删除或批量清理审计记录的业务 API；非管理员和未登录访问不得泄露记录是否存在、操作者或差异内容。

#### Scenario: 管理员查看关键字段差异
- **GIVEN** 管理员已从列表选择一条合法审计记录
- **WHEN** 管理员打开详情
- **THEN** 系统以只读方式展示操作者、时间、对象、对象 ID、动作和结构化关键字段差异
- **AND** 未知但合法的详情键以安全文本展示而不执行 HTML 或脚本

#### Scenario: 普通用户不能访问审计记录
- **GIVEN** 已登录用户不具有管理员角色
- **WHEN** 用户请求审计列表或任意记录详情
- **THEN** 系统返回统一 `403`
- **AND** 响应不表明目标记录是否存在

#### Scenario: 未登录用户不能访问审计记录
- **GIVEN** 请求没有有效登录身份
- **WHEN** 请求审计列表或详情
- **THEN** 系统返回 `401` 且不包含任何审计数据

#### Scenario: 审计写接口不存在
- **GIVEN** 任意用户尝试通过应用 API 修改或删除审计记录
- **WHEN** 请求到达服务端
- **THEN** 系统不暴露对应写入能力且审计记录保持不变

### Requirement: 管理员可查看分项系统运行信息
系统 SHALL 向管理员提供只读运行信息，至少包含应用版本、数据库状态、磁盘总量与剩余空间、最近备份、最近导入和最近失败。每个分项 MUST 具有稳定的 `ok`、`warning`、`error` 或 `unknown` 状态、观测时间及安全摘要；整体状态 MUST 由分项中最严重状态决定。

#### Scenario: 所有运行分项正常
- **GIVEN** 应用版本可确定、数据库探测成功、磁盘空间充足且备份和导入状态可读取
- **WHEN** 管理员打开运行状态页
- **THEN** 页面展示每个分项的状态、观测时间和允许公开的摘要
- **AND** 整体状态为 `ok`

#### Scenario: 单一分项故障仍返回其他诊断
- **GIVEN** 管理员身份已完成校验且一个运行分项探测失败
- **WHEN** 管理员请求运行信息
- **THEN** 响应仍包含其他可用分项
- **AND** 失败分项为 `error` 或 `unknown` 并提供可操作但不泄密的说明
- **AND** 整体状态反映最严重分项

#### Scenario: 非管理员不能查看内部运行详情
- **GIVEN** 用户未登录或不具有管理员角色
- **WHEN** 用户请求详细运行信息
- **THEN** 系统分别返回 `401` 或统一 `403`
- **AND** 响应不泄露数据库地址、磁盘路径、备份文件路径、主机信息或异常堆栈

### Requirement: 运行分项采用明确且安全的数据来源
应用版本 MUST 来自构建或部署元数据；数据库状态 MUST 通过有时限的轻量只读探测取得；磁盘状态 MUST 仅检查配置的持久化路径所在文件系统；最近导入和最近失败 MUST 来自 `import_batch`；最近备份 MUST 来自配置目录内符合版本化契约且通过安全校验的状态文件。系统 MUST NOT 因展示状态而执行备份、扫描任意目录或访问互联网。

#### Scenario: 尚无备份状态产物
- **GIVEN** 备份状态文件未配置或不存在
- **WHEN** 管理员读取运行信息
- **THEN** 最近备份分项显示 `unknown` 和“未配置”或“无记录”
- **AND** 系统不创建文件、不启动备份且不把缺失虚构为成功

#### Scenario: 非法备份状态文件被安全拒绝
- **GIVEN** 配置目录内的备份状态文件超出大小限制、格式非法、契约版本未知或包含目录外路径
- **WHEN** 系统读取运行信息
- **THEN** 最近备份分项显示 `error`
- **AND** 响应不回显文件正文、绝对路径或凭据

#### Scenario: 导入状态区分最近导入与最近失败
- **GIVEN** `import_batch` 同时存在最近成功批次和更早或更新的失败批次
- **WHEN** 管理员读取运行信息
- **THEN** 最近导入分项展示最新批次的状态及安全摘要
- **AND** 最近失败分项展示最新失败批次或明确表示无失败记录

#### Scenario: 探测有时间与范围边界
- **GIVEN** 数据库探测阻塞或配置的持久化路径不可访问
- **WHEN** 运行信息请求超过对应探测时限
- **THEN** 系统终止该分项探测并返回 `error` 或 `unknown`
- **AND** 请求不递归扫描文件、不访问未配置路径且其他分项继续返回

### Requirement: 基础健康检查不泄露内部详情
系统 MUST 保留无需详细运维权限即可调用的基础健康检查，用于判断应用进程是否存活；该响应 MUST NOT 包含数据库连接串、主机路径、备份名称、导入内容、异常堆栈或其他内部诊断详情。详细运行状态与基础健康检查 MUST 使用不同的授权和响应契约。

#### Scenario: 基础存活检查成功
- **GIVEN** 应用进程能够处理请求
- **WHEN** 调用方请求基础健康检查
- **THEN** 系统返回最小化的存活状态和稳定 HTTP 状态码
- **AND** 响应不包含管理员运行信息中的内部摘要

#### Scenario: 详细状态不会退化为公开健康响应
- **GIVEN** 未授权调用方能够访问基础健康检查
- **WHEN** 调用方尝试从该响应推断数据库、磁盘、备份或导入状态
- **THEN** 响应中不存在这些分项及其标识信息
