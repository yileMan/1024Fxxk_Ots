## Why

现有漏洞目录已经提供基础组合筛选和单条漏洞事实，但用户还不能从一个统一入口稳定查询跨产品评估结果，也不能沿 CVE 查看“导入批次 → OTS/CVE 候选 → 产品评估修订 → 提交与审核”的完整业务链。当前没有可用的 EOL 业务输入，KEV 数据源也尚未启用，因此本 change 先交付基于现有 NVD、候选、产品评估和审核数据的查询与追溯闭环，避免等待 OTS-18 阻塞查询能力。

## What Changes

- 将 OTS-19 的实施依赖调整为已完成的 OTS-11、OTS-15、OTS-16 和 OTS-17，不再以 OTS-18 完成为前置条件。
- 扩展漏洞评估组合查询，统一支持 CVE、OTS、产品、产品版本、当前评估状态、CVSS v3.1 严重度和来源发布时间/修改时间的交集筛选、白名单排序及稳定分页。
- 提供从 CVE 出发的只读追溯接口与页面，按层展示当前来源事实及最近成功导入批次、可见 OTS/CVE 候选、授权范围内的产品评估完整修订链，以及每个修订保存的提交与审核事件。
- 所有列表总数、追溯节点和详情跳转均执行相同的产品范围裁剪；管理员可查看全局数据，普通用户不得通过数量、ID 或关联节点推断未授权产品信息。
- 将有效筛选、排序和分页参数编码到 URL，支持复制链接、刷新及浏览器前进/后退后恢复；非法或过期参数返回明确反馈。
- 对关键组合查询执行 MySQL `EXPLAIN` 和代表性数据性能验证，复用或补充既有 11 张基础表上的索引，不引入搜索引擎或新业务表。
- 明确本 change 不实现 EOL 候选、确认、筛选或追溯，也不实现任何新的 KEV 导入、筛选、追溯、复评或性能任务；既有 KEV 字段和基础筛选仅保持兼容，不以其作为本 change 的验收条件。
- 不实现评估导出、数据库变更审计查询或运维页面，分别保留给 OTS-20 和 OTS-21。

## Capabilities

### New Capabilities

- `global-search-and-traceability`: 定义跨漏洞、OTS、产品与评估状态的统一查询，以及从 CVE 到导入批次、候选、产品评估修订和审核事件的授权追溯行为。

### Modified Capabilities

- `vulnerability-catalog-and-workbench`: 将既有漏洞目录扩展为可分享、可排序且支持产品版本条件的统一组合查询入口，并明确 OTS-19 不新增 EOL/KEV 行为。

## Impact

- 后端：扩展漏洞目录的 schema、repository、service 和 API 路由，新增只读追溯查询；可能增加一份编号化索引迁移及对应回滚说明，但基础表数量保持 11 张。
- 前端：扩展漏洞目录筛选与排序，新增 CVE 追溯视图及路由，继续使用 OpenAPI 生成的 TypeScript 类型。
- 授权：复用 OTS-05 的有效产品/版本范围，管理员全局只读；普通用户只看到至少一条授权产品评估所支撑的漏洞及对应裁剪后链路。
- 规格与文档：覆盖 FR-WORK-003 中除新增 KEV 工作外的查询能力、FR-WORK-004 和 NFR 12.2，并在实施时更新 `doc/Task.md` 中 OTS-18/OTS-19 的依赖、范围及编号错位。
- 依赖 change：OTS-11、OTS-15、OTS-16、OTS-17；OTS-18 明确暂缓且不阻塞本 change。
