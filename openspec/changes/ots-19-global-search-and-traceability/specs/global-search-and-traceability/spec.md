## Purpose

本能力为管理员和具有有效产品范围的普通用户提供统一、稳定且可分享的漏洞评估组合查询，并从 CVE 出发只读追溯来源批次、OTS/CVE 候选、产品评估完整修订链及其提交审核事件，同时防止通过关联节点或数量泄露未授权产品数据。

## ADDED Requirements

### Requirement: 提供非 EOL/KEV 增量范围的统一组合查询
系统 SHALL 支持按 CVE、OTS、产品、产品版本、当前产品评估状态、来源 CVSS v3.1 严重度、来源发布时间区间和来源修改时间区间进行交集查询。系统 MUST 对所有条件先执行产品范围裁剪再计算总数，MUST 提供白名单排序字段与升降序、以唯一标识作为稳定次序，并 MUST 拒绝未知排序字段、非法枚举、无效标识、反向时间区间及越界分页。本 change MUST NOT 新增 EOL 查询，也 MUST NOT 新增或扩大 KEV 导入、查询或追溯行为；既有 KEV 字段和基础筛选仅保持兼容。

#### Scenario: 多条件交集命中授权范围内结果
- **GIVEN** 当前用户对一个产品版本具有有效范围，系统中同时存在符合和不符合指定 OTS、产品版本、状态、严重度及时间区间的漏洞评估
- **WHEN** 用户提交全部条件并按来源修改时间降序查询
- **THEN** 系统只返回同时符合全部条件且位于有效范围内的漏洞，并给出裁剪后的正确总数和稳定顺序

#### Scenario: 管理员查询没有产品评估的漏洞
- **GIVEN** 一个已成功导入的 CVE 尚无候选或产品评估
- **WHEN** 管理员仅按 CVE 查询
- **THEN** 系统返回该漏洞并将可追溯候选及评估数量标为零

#### Scenario: 普通用户不能看到仅存在于范围外的漏洞
- **GIVEN** 一个 CVE 只关联未授权产品版本的评估
- **WHEN** 普通用户按精确 CVE 或其他组合条件查询
- **THEN** 系统返回空分页结果且总数为零，不暴露范围外产品、候选、评估或数量

#### Scenario: 拒绝非法查询参数
- **WHEN** 用户提交未知排序字段、非法状态、非正整数标识、开始时间晚于结束时间或超出上限的分页参数
- **THEN** 系统返回 `422` 字段级错误且不执行降级查询、不写入 `audit_log`

### Requirement: 从 CVE 追溯来源事实和导入批次
系统 SHALL 为可见 CVE 返回追溯根节点，包含 CVE 标识、当前来源状态、发布时间、来源修改时间、内容哈希和最近成功导入批次摘要。批次摘要 MUST 使用漏洞当前保存的导入批次引用，至少返回内部批次 ID、批次号、来源标识、来源发布标识、来源时间窗口、包摘要、导入完成时间和状态；系统 MUST NOT 返回服务器文件绝对路径、Cookie、完整包内容、密钥或失败批次的敏感错误正文。

#### Scenario: 查看当前事实对应的最近成功批次
- **GIVEN** 一个可见 CVE 经多个批次更新且当前事实指向最近成功批次
- **WHEN** 用户打开该 CVE 的追溯视图
- **THEN** 系统返回当前事实及其实际引用的最近成功批次摘要，不以全局最新批次替代该引用

#### Scenario: 当前事实没有可用批次元数据
- **GIVEN** 一个迁移或测试产生的可见漏洞没有可解析的导入批次引用
- **WHEN** 用户打开追溯视图
- **THEN** 系统保留漏洞事实并明确标记批次信息不可用，不伪造批次号或时间

### Requirement: 追溯候选及产品评估完整修订链
系统 SHALL 在同一 CVE 追溯响应中按 OTS 稳定分组返回可见候选摘要，并在候选下返回授权产品版本对应的产品评估链。候选至少包含匹配记录 ID、OTS、匹配方式、可读依据、首次和最近来源批次；每条评估链至少包含产品、产品版本、产品 OTS、当前评估 ID以及按 `revision_no` 升序排列的全部修订。每个修订 MUST 返回修订 ID、父修订 ID、修订号、当前标记、状态、负责人、提交人及时间、审核决定、审核人及时间、退回或修订原因和变化摘要，且 MUST 明确“候选不等于产品受影响”。

#### Scenario: 展示退回重提和自动复评形成的完整链
- **GIVEN** 授权产品的某个 OTS/CVE 先后经历初次提交、审核退回、重新提交通过和自动待复评
- **WHEN** 用户查看 CVE 追溯
- **THEN** 系统按连续修订号展示全部历史和当前修订及其父子关系、状态、提交与审核事件，不只返回当前记录

#### Scenario: 候选尚未生成产品评估
- **GIVEN** 管理员可见一个 OTS/CVE 候选但尚无任何产品评估
- **WHEN** 管理员查看 CVE 追溯
- **THEN** 系统展示候选依据和来源批次并明确评估链为空，不把候选解释为产品受影响

#### Scenario: 历史修订保留当时事件
- **GIVEN** 产品版本当前负责人或审核人已经变更，历史修订保存了实际提交人与审核人
- **WHEN** 有权用户查看追溯链
- **THEN** 历史节点显示修订自身保存的实际事件人员与时间，当前分配仅作为当前产品版本信息且不得覆盖历史

### Requirement: 所有追溯节点统一执行产品范围裁剪
系统 MUST 要求可恢复的当前用户身份。管理员 SHALL 可只读查看全部 CVE 追溯；普通用户 SHALL 只能读取至少存在一个有效授权产品评估的 CVE，并只能看到由其有效产品版本范围支撑的候选、产品、评估和修订节点。系统 MUST 在查询层裁剪后再计算节点数；直接猜测 CVE、候选、评估、修订或批次 ID 不得绕过授权，也不得通过空分组、计数或错误差异泄露范围外关联。

#### Scenario: 混合授权产品的链路被整体裁剪
- **GIVEN** 同一 CVE 和 OTS 分别关联授权产品 A 与未授权产品 B 的评估链
- **WHEN** 普通用户读取追溯视图
- **THEN** 系统只返回产品 A 的链和由产品 A 支撑的候选，所有计数均基于裁剪后结果且不出现产品 B 的名称、版本、人员或状态

#### Scenario: 直接访问完全越权的 CVE
- **GIVEN** 普通用户知道一个只关联未授权产品的漏洞 ID
- **WHEN** 用户直接请求该漏洞追溯接口
- **THEN** 系统返回稳定的 `403`，不返回来源事实、批次、候选、评估数量或其他受保护内容

#### Scenario: 未登录请求追溯
- **WHEN** 没有可恢复身份的客户端请求任一追溯接口
- **THEN** 系统返回 `401` 且不返回任何业务节点

### Requirement: 查询和追溯保持只读且满足正常规模性能目标
组合查询和追溯 SHALL 为纯读取操作，不得改变评估状态、行版本、修订链、候选、批次或审计记录。系统 MUST 在项目正常规模及 10～20 个并发在线用户条件下，使常用组合查询和 CVE 追溯详情 95% 请求在 3 秒内返回；分页列表和追溯查询 MUST 使用可验证的既定索引访问路径，不得依赖独立搜索引擎或新增业务表。

#### Scenario: 重复查看不产生业务变化
- **GIVEN** 用户连续执行同一组合查询并多次刷新同一 CVE 追溯页
- **WHEN** 所有读取成功或其中一次因权限、校验或服务错误失败
- **THEN** 评估状态、行版本、修订数、候选、批次和 `audit_log` 条数均保持不变

#### Scenario: 代表性数据满足性能门槛
- **GIVEN** 数据库包含项目正常规模的产品、OTS、漏洞、候选和十年保留期代表性评估修订数据
- **WHEN** 在 10～20 个并发用户下执行常用组合查询和追溯详情场景
- **THEN** 95% 请求在 3 秒内返回且关键 SQL 的执行计划使用预期索引而非不可接受的全表扫描

### Requirement: 前端提供可恢复的查询和分层追溯视图
前端 SHALL 将有效筛选、排序、页码和每页数量编码到路由查询参数，并在复制链接、刷新及浏览器前进或后退后恢复同一查询。CVE 追溯页 SHALL 按“来源与批次、候选 OTS、产品评估链、修订与审核事件”分层展示裁剪后的结果，并为加载、空结果、无权访问、参数校验失败和服务失败提供可区分状态。页面 MUST 将所有来源文本、依据、原因和事件内容按纯文本呈现，不得将其作为 HTML 执行。

#### Scenario: 分享链接恢复相同结果页
- **GIVEN** 用户应用多个筛选条件、排序方式和非首页页码
- **WHEN** 用户复制当前 URL 并在新的已登录页面打开
- **THEN** 页面恢复相同有效参数并请求相同查询，不静默退回默认条件

#### Scenario: 浏览器返回恢复先前筛选
- **GIVEN** 用户从组合查询结果进入 CVE 追溯页
- **WHEN** 用户使用浏览器返回
- **THEN** 查询页恢复进入详情前的筛选、排序和页码，并可继续浏览

#### Scenario: 追溯文本包含标记字符
- **GIVEN** 来源描述、候选依据或修订原因中包含 HTML 标记或脚本样式文本
- **WHEN** 页面展示追溯节点
- **THEN** 页面以纯文本显示内容且不执行标记或脚本
