## Context

当前后端以本地用户表、密码摘要、账号状态和签名 Cookie 实现登录；前端依靠 `/api/v1/auth/me`、认证状态和路由守卫恢复与维持身份。本 change 将其收敛为一次性用户名密码匹配。详细动机见 `proposal.md`；实施仍须满足单体架构和 11 张应用基础表约束，且不得删除既有用户数据。

## Goals / Non-Goals

**Goals:**

- 保留用户名、密码提交与匹配成功/失败的登录流程。
- 删除 Cookie 签名、时效、令牌、账号状态、来源及密码策略等额外认证校验。
- 使前端在登录成功后写入用户 ID Cookie，并在后续请求中恢复当前身份。
- 对需要登录的页面使用轻量路由守卫，未恢复到当前用户时跳转登录页并保留站内目标地址。
- 在 OpenSpec 项目配置中固化仅用户名密码校验的约束。

**Non-Goals:**

- 不新增授权、角色访问控制、SSO、MFA、默认身份或替代登录方案。
- 不将密码明文持久化；密码摘要存储不构成额外认证判断条件。
- 不删除已部署数据库中的用户记录或认证迁移。

## Decisions

### 登录只进行凭据匹配

登录端点接收登录名和密码，只检查目标用户记录是否存在且密码摘要匹配；成功返回公开用户信息，失败返回统一登录失败结果。账号启停、密码长度/复杂度、Cookie 签名、过期时间和请求来源均不参与判断。替代方案是保留账号状态或密码规则；这些都会引入用户明确要求移除的附加认证条件，故不采用。

### 使用未签名用户 ID Cookie 传递身份

登录成功设置 `ots_user_id` Cookie，值仅为用户 ID；后续请求读取该值并查询用户记录以取得角色、产品范围和审计操作者。Cookie 不签名、不设置固定过期时间，也不校验请求来源或账号状态。替代方案是无状态登录；它无法支撑既有授权与审计，故不采用。

### 使用当前用户结果驱动轻量路由守卫

`/system` 等业务路由标记为需要登录。守卫复用 `restoreAuthentication()`：取得用户时放行，未取得用户时跳转 `/login?redirect=<目标路径>`；登录页本身和健康页不拦截。守卫只改善导航流程，不增加后端认证条件。替代方案是把根路径直接改到登录页，但会丢失用户最初请求的业务地址，故不采用。

### 保持密码摘要和用户数据

继续使用已有密码摘要进行匹配，并保留 `app_user` 表和数据；仅移除与账号状态、角色和会话有关的运行时依赖。摘要存储保护静态数据，不增加额外登录分支。替代方案是改存明文密码，但会扩大数据泄露风险且并非实现用户名密码匹配所必需，故不采用。

### 在项目配置禁止认证附加机制

更新 `openspec/config.yaml` 的项目上下文，明确未来登录仅允许用户名密码匹配和用户 ID Cookie 身份传递，禁止引入 Cookie 签名、时效、令牌、来源、账号状态及其他认证附加机制。替代方案是只在本 change 中声明；归档后无法约束后续 change，故不采用。

## Risks / Trade-offs

- [Cookie 中的用户 ID 可被客户端修改] → 这是用户要求移除 Cookie 签名校验的直接结果；服务端仍按该 ID 加载角色、产品范围和审计操作者。
- [守卫与应用启动同时恢复身份导致重复请求] → `restoreAuthentication()` 复用同一个初始化 Promise，确保并发导航只调用一次当前用户接口。
- [无法区分停用账号] → 这是仅凭据匹配约束的直接结果；管理流程不得依赖登录时的账号状态限制。
- [外部调用方依赖 `/api/v1/auth/me`、退出或 Cookie] → 作为破坏性变更，在发布说明中列出移除端点和客户端适配要求。

## Migration Plan

1. 先为仅用户名密码匹配、未签名用户 ID Cookie 以及无需来源校验补充回归测试。
2. 删除 Cookie 签名、来源、账号状态和密码策略相关代码与前端依赖，保留登录端点、用户 ID Cookie 和密码摘要匹配。
3. 更新 OpenAPI、生成的 TypeScript 类型、配置示例与 OpenSpec 项目配置。
4. 对既有部署不执行删除用户表或数据的迁移；部署后要求调用方停止依赖被移除端点。
5. 运行后端、前端、端到端和 OpenSpec 严格校验。回滚时恢复认证附加机制的代码与契约；用户数据无需恢复。
