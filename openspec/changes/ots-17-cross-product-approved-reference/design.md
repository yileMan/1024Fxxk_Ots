## Context

参见 `proposal.md` 的 Why。现有评估详情由 `/api/v1/assessments/{assessment_id}` 提供目标评估、来源事实、候选依据、环境评分、动作能力和修订上下文，后端已按 routes、schemas、services、repositories 分层，前端统一在 `AssessmentDetailPage.vue` 展示。OTS-15/16 已固定“每个产品 OTS/CVE 只有一个当前修订”以及历史修订只读语义。

本 change 必须在现有 11 张应用基础表内完成。跨产品定位通过目标 `product_assessment.product_ots_id` 关联 `product_ots.ots_component_id`，再以相同 `ots_component_id` 和 `vulnerability_id` 查询其他产品；产品身份通过产品版本关联产品取得。参考数据是经过批准的最小跨范围摘要，不等于授予用户其他产品详情权限。

## Goals / Non-Goals

**Goals:**

- 在数据库查询层一次性落实相同 OTS/CVE、排除同一产品、当前修订、完成状态和批准决定约束。
- 以独立响应模型执行字段白名单，使 repository 未选择、schema 未声明、前端未接收敏感字段。
- 复用目标评估详情的读取授权作为入口门，允许负责人和审核人在同页读取跨范围但受限的批准摘要。
- 将参考区故障隔离于当前评估主体，保持既有编辑、提交和审核流程可用。
- 在既有规模下保持确定性结果顺序，并证明查询不产生数据库写入和审计。

**Non-Goals:**

- 不提供参考评估详情跳转、历史参考、搜索筛选、导出、复制或自动填充。
- 不改变评估状态机、修订创建、产品范围授权、自动复评指纹或审计规则。
- 不新增表、字段、索引、迁移、缓存或后台任务；OTS-19 再处理全局查询、分页和索引优化。

## Decisions

### 1. 使用目标评估下的独立只读子资源

新增 `GET /api/v1/assessments/{assessment_id}/approved-references`，返回摘要数组。service 先按现有评估详情相同的认证、产品范围和可见性规则解析目标评估，再把目标的 `product_id`、`ots_component_id` 和 `vulnerability_id` 交给 repository 查询。

选择独立子资源而不是把数据嵌入评估详情，是为了让参考区能独立加载、失败和重试，避免参考查询失败阻断当前评估；也避免扩大现有详情响应及每次保存、提交、审核后的返回负担。未采用允许客户端提交 OTS/CVE/product 参数的通用查询接口，因为客户端参数可能被组合用于枚举跨产品数据，且会重复目标评估授权逻辑。

### 2. 在 SQL 投影前完成筛选和字段白名单

repository 从目标产品 OTS 关联定位 `ots_component_id`，连接其他 `product_ots`、`product_version`、`product` 和 `product_assessment`，使用 `vulnerability_id` 锁定同一 CVE，并应用以下谓词：

- 参考产品 ID 不等于目标产品 ID；
- `product_assessment.is_current = 1`；
- `product_assessment.status = 'completed'`；
- `product_assessment.review_decision = 'approved'`。

查询只投影产品名称、版本、适用性、分析摘要、环境分数、处置方式和审核完成时间，按审核完成时间降序、产品名称和版本升序形成稳定结果。service 不接收 ORM `ProductAssessment` 实体，schema 使用专用严格响应模型，防止以后给详情模型加字段时意外扩大披露。

未采用“先查所有修订再由 service 过滤”，因为这会让草稿、历史证据和审核意见进入更高层内存，增加误返回和测试漏网风险。未回退到历史批准修订；“当前且已审核通过”是一个同时成立的快照条件。

### 3. 入口授权与摘要跨范围读取分离

用户必须先通过目标评估既有详情读取授权；无权时沿用既有拒绝和资源隐藏语义。通过入口门后，其他产品摘要不再套用普通产品范围裁剪，否则产品负责人无法满足 FR-ASSESS-011 的跨产品参考目标。这个例外只适用于专用白名单响应，不授予参考评估 ID、详情页或任何写接口权限。

管理员通过其既有全局目标评估读取能力可查看相同摘要；负责人和审核人的可见性由目标评估既有规则决定。前端隐藏区域或按钮不承担授权职责。

### 4. 前端独立状态且不连接表单赋值路径

`assessmentEditor.ts` 增加专用摘要类型和读取函数；`AssessmentDetailPage.vue` 在候选匹配与当前产品结论之间增加参考区域。区域维护独立的 loading/error/items 状态，在目标详情成功后发起请求；失败只提供重试，不改变详情、表单、动作能力或冲突状态。

摘要卡片只渲染白名单字段，空环境分数显示“未提供”，空集合显示“暂无其他产品的当前已审核参考”。组件不实现任何向草稿模型赋值的处理器，也不提供参考详情链接，从结构上保证“仅供参考”。加载新 assessment ID 时清空旧摘要，避免路由切换期间短暂展示错误产品上下文。

### 5. 契约和测试以泄露防护为首要验收门

OpenAPI 生成专用 response schema 并重新生成前端类型。后端测试直接构造混合产品、版本、状态、修订和敏感字段数据，断言只返回其他产品的当前批准摘要且 JSON key 集合精确等于白名单；另验证无权入口、空结果、稳定排序以及查询前后评估和审计计数不变。

前端组件测试覆盖成功、空、失败重试、环境分数缺失、无复制/跳转控件及参考刷新不改表单。Playwright 使用系统 Chrome 验证负责人和审核人的同页旅程，并通过网络响应确认敏感字段不存在。OpenAPI 漂移、后端 pytest、前端 Vitest/覆盖率、生产构建和 OpenSpec 严格校验作为交付门。

## Risks / Trade-offs

- [跨范围摘要被未来字段扩展意外放大] → repository 显式列投影、专用严格 schema、JSON key 精确断言三层白名单。
- [历史批准记录在当前修订待复评时被错误回退展示] → SQL 同时限定当前标记、完成状态和批准决定，并用父子修订混合数据回归。
- [同一产品其他版本被误认为“其他产品”] → 以产品 ID 而非产品版本或 `product_ots_id` 排除目标产品，并建立多版本测试。
- [独立请求造成额外查询和页面局部延迟] → 参考区异步加载并隔离失败；复用现有外键和唯一当前修订约束，在 OTS-19 前不新增预设索引或缓存。
- [返回完整数组在极端产品规模下过大] → V1 基线最多约 200 个产品，固定小字段投影可接受；若真实规模或测量不满足 3 秒目标，由 OTS-19 统一引入分页和索引设计。
- [当前参考随其他产品新修订变化，不是目标评估提交时快照] → 页面明确展示“当前已审核参考”和审核完成时间；本 change 不持久化参考快照。

## Migration Plan

1. 先增加 repository、service、专用 schema 和只读路由及后端测试，不执行数据库迁移。
2. 更新 OpenAPI 并重新生成 TypeScript 类型，确认连续生成无漂移。
3. 增加前端 API、参考区域及组件测试，再以系统 Chrome 完成负责人和审核人纵向验收。
4. 部署后旧前端不调用新子资源，后端新增 GET 接口保持向后兼容；回滚时先回退前端，再移除后端接口即可，无数据回滚。
